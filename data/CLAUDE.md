# data/

Pure data, no game logic. Catalogs are GDScript dictionaries built once and cached.
PROTOTYPE: data lives in code for fast iteration; can move to .tres later.

## Architecture
- `roster.json` (GENERATED by tools/roster/build_roster.py, do not hand-edit): 144 units (kits: stats 1..9,
  keywords, actions, triggers, flags, 3 rank-ups, champion relic), tokens, monsters, form sprites, keyword registry.
- `roster.gd` (`Roster`): loads roster.json.
- `config.gd` (`GameConfig`): every tunable number (economy, shop, stat units HP_UNIT/ATK_UNIT, keyword units).
- `keywords.gd` (`Keywords`): keyword registry (from the roster), faction ring, archetypes = factions.
- `units.gd` (`UnitCatalog`): unit defs from the roster (HP x HP_UNIT, Attack x ATK_UNIT, Speed raw).
- `kits.gd` (`Kits`): actions after upgrade cards, default rules, rank-up cards.
- `items.gd` (`ItemCatalog`): 33 items = stats (game units) + a mod (kw/trig/acts/flags) + optional requirement.
- `relics.gd` (`RelicCatalog`): team relics as mods (optionally one faction) or economy relics.

## Etiquette
- Units/kits: edit tools/roster/build_roster.py (KITS / TOKENS / MONSTERS) and rerun it. New steps,
  selectors or keywords need a case in modules/battle/battle_sim.gd (vocabulary listed in its CLAUDE.md).
- Item/relic: one `_i(...)` / `_r(...)` line; the mod uses the same vocabulary as rank-up cards.
- Sprite/icon names must exist in `art/duelyst/`.
